The policy point: where compliance belongs in the JVM

Every configurable system has two spaces. Most of operations lives in one of them. Production-evidence and compliance requirements lie partly in the other, and that is the whole argument for Eliya JDK and its one flag.

This is the thesis behind Eliya. For what actually ships, see the diff from upstream and the flags reference.

The placement claim, in one paragraph

Let F be the set of behaviours reachable by composing a runtime's existing flags. Every wrapper script, Helm chart, and admission webhook is a selector over F. A requirement that lies outside F cannot be met by any selector. It can only be met by extending the runtime itself. Production-evidence and compliance requirements lie partly outside F. So the policy point belongs inside the VM: named as policy, implemented as mechanism, shipped as a default.

Two spaces

Every configurable system has two spaces. The configuration space is every behaviour you can reach by setting the knobs the system already exposes. The capability space is the set of behaviours that exist only if someone changes the system itself. Wrapper scripts, Helm charts, admission webhooks, GitOps: all of it selects points in the configuration space. None of it extends the space. Only whoever builds the runtime can do that.

Most of operations is selection, and that is fine. Most requirements live inside the configuration space. The interesting problems start when a requirement does not.

Policy and mechanism

Operating-systems research named this boundary fifty years ago: policy/mechanism separation. Policy names an intent; mechanism implements it. A JVM flag like -XX:+HeapDumpOnOutOfMemoryError is mechanism. "This JVM runs production workloads in a regulated environment, so behave accordingly" is policy. The JVM exposes hundreds of the former and exactly none of the latter.

Two more pieces complete the thesis.

Defaults are policy

Defaults are policy, whether or not anyone intends them to be. Johnson and Goldstein measured organ-donor consent at around 12% in Germany and over 99% in Austria, two culturally similar countries, on nothing but which box was pre-ticked. People run what ships. Whatever a JDK distribution defaults to is, in practice, the configuration of the fleet.

Every contact leaves a trace

Borrowed from forensic science: Locard's exchange principle holds that every contact leaves a trace. Production incidents obey it too, but only if the runtime is configured to record the trace. An out-of-the-box JVM is a crime scene that wipes itself: no GC log, no heap dump, and a crash log written to an ephemeral path that dies with the container.

Where requirements fall outside F

Three concrete examples of requirements that no external selector can satisfy.

  • PCI DSS Requirement 3.5.1 says the primary account number must be rendered unreadable anywhere it is stored. A heap dump of a payment service stores live card numbers in cleartext, which makes dump contents a dump-writer problem inside the VM, not a flag anyone can set from outside it.
  • SOX-style change control wants attestation that the running configuration is the approved one. A flag's origin, whether the profile set it or someone's command line did, is internal VM state, invisible to any external tool.
  • ISO 27001 control A.8.15 wants logs produced and protected, including artefacts written during a crash, by crash-path code that only the VM runs.

The cash value is one flag

The cash value of all this theory is a single flag:

java -XX:EliyaProfile=Production -jar app.jar

That flag ships in Eliya JDK 25.0.3, an OpenJDK 25 LTS distribution from Asymm Systems, built for compliance-conscious production in telecom, banking, healthcare, and government. EliyaProfile is the policy point the thesis calls for: a named enum, not a boolean, because policies are named things. Production today; compliance-aligned values, demand-gated, later. It is the same Java you already run, built from the upstream OpenJDK 25 source tree under GPLv2 with the Classpath Exception, with no API changes. The difference shows up when something fails in production: the diagnostic evidence is already on disk, and it stays inside your perimeter.

A note on the name

Eliya is short for Nuwara Eliya, the highland tea country of Sri Lanka. In Sinhala the word means light. Java took its name from an Indonesian island that grows coffee; ours comes from highlands that grow tea.
