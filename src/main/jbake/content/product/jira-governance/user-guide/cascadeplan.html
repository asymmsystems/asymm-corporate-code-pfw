CascadePlan Guide

CascadePlan User & Administrator Guide

How to plan Jira work on a canvas timeline with percent-trigger dependencies, see why each task starts when it does, review and undo every Jira write, add contributors as Jira sub-tasks, and work with the table view, the keyboard and multiple plans.

1. The Planner

Open CascadePlan Planner from the project navigation. The planner shows the project's tasks in a list on the left and a canvas timeline on the right:

  • Zoom: switch between Day, Week, Month, Quarter and Year. Today jumps to the current date.
  • Hierarchy: show all issues, epics only, or stories and tasks.
  • Create: + Epic and + Task create Jira issues from the planner.
  • Backlog: the Backlog tray lists issues without dates so you can schedule them.
  • Columns: show, hide and resize the task list columns.

Figure 1: The planner in Compact view: epics with their stories, tasks and sub-tasks on the week timeline, with links that start at 30% or 50% of their predecessor.

2. Percent-Trigger Dependencies & Why-Explanations

A task can start when its predecessor reaches a set percent, not only when it is 100% done. For example, start the API integration when the database design reaches 30%.

  • Add a dependency: click a task bar and choose Add dependency, or drag the arrow from one bar to another. Set Starts when that issue reaches (percent).
  • Why this date? Select a task and press ?, or choose Why this date? from the task menu. The popup names the driving task, the trigger percent and the driving dates.
  • Conflicts: if you drop a task before its predecessor reaches the trigger, a dialog names the predecessor and offers fixes, such as Adjust Trigger to Fit.
  • Enforce deps: when this box is checked, moving a task snaps it to respect its predecessors.
  • Change a link: click an arrow, or its percent label, to change its percent or remove it. Every link of a task has its own arrow and label.

Each dependency is a Jira "Blocks" link, so it is the same in every plan, and its trigger percent is stored on the successor issue (the issue property cascadeplan.links). Remove Link deletes exactly that Jira link, whoever created it. A parent's dependencies also hold back its sub-tasks.

3. Transparent Jira Writes, Preview & Undo

CascadePlan writes to Jira only the values you change, as you:

  • Preview: while you drag a bar, a preview shows the planned Jira updates for the task and the tasks that move with it.
  • Undo: after each write a flag with Undo appears for 10 seconds. Ctrl+Z undoes and Ctrl+Shift+Z redoes, up to 20 steps.
  • Changes panel: click Changes in the toolbar to see "Jira writes in this session", with the old value, the new value and the result of each write.

Jira writes include issue fields you edit (dates, assignee, summary, estimates), status transitions, new issues, epics and sub-tasks, and the issue links that mirror dependencies.

4. Contributors as Jira Sub-Tasks

A Jira issue has one assignee. To add more people to a task, open the task and use Multi-Resource Allocation (Jira Subtasks):

  1. Choose a team member, enter the hours and click + Allocate Resource. CascadePlan creates a Jira sub-task assigned to that person, so the work shows in their own queue.
  2. To remove a contributor, choose Delete sub-task or Unassign sub-task, or Cancel.

Create sub-task in Jira in the same dialog creates a plain Jira sub-task, with an estimate only if you type one.

5. Table View, Keyboard & Search

  • Table view: choose Table in the view selector to see all tasks and dates in a table instead of the canvas.
  • Keyboard: arrow keys move between tasks. Space enters move mode on a task; arrow keys and [ ] then shift its dates.
  • Search: Ctrl+F opens in-app search to find a task by key or summary.

6. Estimation Units

Each task can use its own Estimation Unit: Hours, Story Points (1 point = 8 hours) or T-Shirt Size (XS, S, M, L, XL). CascadePlan keeps the unit you chose and converts the value to hours for scheduling. It does not change Jira fields you did not change.

7. Multiple Plans

Click the plan selector (for example Main Plan) to open Manage Project Plans. Plan approvers can create a new plan, optionally cloning the current plan, and rename or delete plans; anyone can switch plans. The main plan cannot be deleted. Dates, dependencies and the hierarchy belong to Jira, so they are the same in every plan; each plan keeps its own row order, columns and milestones.

Work items in this plan (JQL filter). A plan reads at most the newest 1,000 work items of the project. For a larger project, a plan approver can narrow the open plan with a JQL filter in the plan list, for example fixVersion = "2.0", and choose Save filter. Jira checks the filter first, and CascadePlan says how many work items match. Work outside the filter is not shown, and a move does not move it. Clear the field and save to read the whole project again.

7a. Moving a Task with Its Sub-Tasks

Drag the bar of a task or story that has sub-tasks, or move it with the keyboard or the toolbar: the whole block moves. Sub-tasks not started move by the same days; a sub-task in progress keeps its start and moves its end (never before today); a finished sub-task stays. The parent's Jira due date follows its new end, and one Undo restores the block.

7b. Changing a Parent or a Work Type

Drag a row onto the middle of another row (the target is outlined and a label says what will happen), or use Parent in Jira in the task dialog. CascadePlan asks first, then makes the change in Jira: a task under another epic, a sub-task under another task, or a task turned into a sub-task and back (through a Jira bulk move, whose progress is shown). Jira's rules apply; for example a task with sub-tasks cannot become a sub-task. Undo makes the reverse change.

7c. Baselines and Scope Changes

  1. A plan approver chooses Baseline in the toolbar, enters a name and chooses Freeze the plan as a baseline. The baseline records each work item's Jira estimate, start and end.
  2. The Baseline button then shows the change since the freeze, for example +12 h (+25%), 1 added, 2 later, and the panel lists every work item added, removed or changed.
  3. Anyone in the project can write a reason and choose Request approval of this scope. A plan approver other than the requester accepts it (which freezes a new baseline version) or rejects it.
  4. Under Baseline versions: compare a version with the plan or with the active version, export it as CSV with its SHA-256 digest, or make it active.

Each read of a baseline checks its digest and says so if the stored baseline no longer matches what was frozen.

Figure 2: The Baseline panel shows the change since "Sprint 23 commitment": one task added and one estimate raised, 24 hours in all.

8. Utilization View

Choose Utilization in the view selector to see a table of estimated hours per assignee for each of the next 8 weeks. Hours come from tasks that have an assignee, an estimate and dates; each task's hours are spread evenly over its days. No capacity is assumed, so the table does not mark anyone as over-allocated.

9. Administration: CascadePlan Approvers

Jira administrators can open Jira admin settings, Apps, CascadePlan approvers. On this page you can search for Jira groups, add them to the list and click Save changes.

Members of these groups, project administrators and Jira administrators are plan approvers: they create, rename and delete plans, freeze baselines, and accept or reject scope changes. CascadePlan checks this on the server for every such action.
