Open Verifier Guide

Open-Source Offline Cryptographic Verifier

A zero-dependency Node.js CLI verification tool allowing compliance auditors and security teams to independently verify LedgerSeal signatures, snapshot hashes, and audit chains completely offline without trusting Jira or Asymm Systems.

1. Why Offline Verification Matters

In enterprise audits (SOC 2, ISO 27001, FDA 21 CFR Part 11), a critical principle of evidence integrity is independent reproducibility. If compliance evidence can only be validated by querying the proprietary software that generated it, the evidence is subject to circular trust and vendor compromise.

LedgerSeal provides complete cryptographic independence. Every approved ticket can export a standalone evidence JSON document. Our open-source verifier (verify-evidence.mjs) executes entirely on an auditor laptop with zero external network connectivity, using only the Node.js standard library.

2. Zero-Dependency Architecture

The verifier is engineered for extreme audit portability:

  • Zero npm Dependencies: Requires only standard Node.js (v18 or higher) utilizing native node:crypto and node:fs.
  • Air-Gapped Execution: Runs completely offline on isolated, air-gapped auditor workstations.
  • Open-Source Transparency: 100% open source under the Apache-2.0 license. The script is under 300 lines of readable JavaScript.

3. Command-Line Usage

The verifier supports both named CLI flags and positional arguments:

# Positional argument syntax
node verify-evidence.mjs evidence.json public-key.pem

# Named argument syntax
node verify-evidence.mjs --evidence evidence.json --public-key public-key.pem

4. Cryptographic Verification Mechanics

When executed, verify-evidence.mjs performs four discrete cryptographic checks:

Phase Cryptographic Standard Validation Logic
1. Canonical Normalization RFC 8785 (JSON Canonicalization) Normalizes key sorting, whitespace, and Unicode formatting to guarantee deterministic byte serialization.
2. Snapshot Hash Check SHA-256 (FIPS 180-4) Recomputes the cryptographic digest of covered fields and attachments, verifying it matches the recorded snapshot hash.
3. Signature Verification Ed25519 (RFC 8032) Verifies the asymmetric Ed25519 digital signature over the snapshot digest using the published Asymm public key.
4. Chain Continuity Check Hash Chain Linking Inspects every block in the reseal history, validating that prev_hash references the exact SHA-256 digest of the preceding block.

5. Exit Codes for CI/CD & Automated Audits

Security teams can embed the verifier into automated release pipelines or compliance cron monitors:

  • 0 - SUCCESS: Evidence is completely valid, authentic, and untampered.
  • 1 - TAMPERED SNAPSHOT: Computed SHA-256 digest does not match recorded snapshot hash.
  • 2 - INVALID SIGNATURE: Ed25519 signature verification failed against supplied public key.
  • 3 - BROKEN HASH CHAIN: Hash chain continuity failure between reseal blocks.
  • 4 - INVALID INPUT: File not found, invalid JSON syntax, or unreadable public key.
