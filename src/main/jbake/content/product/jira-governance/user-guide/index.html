User Guide

Jira Governance Suite User Guide

Everything you need to evaluate, configure, operate, and audit the Asymm Systems Jira Governance Suite. Organized by application and role: jump directly to the chapter you need.

Quick start for each app

Each app works on its own. Install it from the Atlassian Marketplace, then follow its steps below. The steps marked "Jira administrator" need that role; the others need only the usual Jira permissions of the issue.

CascadePlan (about 5 minutes)

  1. Open a Jira project and choose CascadePlan Planner in the project's navigation.
  2. Drag a work item from the Backlog tray onto the timeline to give it dates.
  3. Drag the arrow at the end of one bar onto another bar, and choose when the second may start (for example 30%).
  4. Move the first bar: read the Jira changes listed before you let go, then let go. Ctrl+Z undoes it.

No setup is needed. CascadePlan guide

Get it on Atlassian Marketplace

LedgerSeal (5 minutes, plus the gate)

  1. Open an issue, open the Approval Seal panel from the issue's app button, choose Seal this issue, then Sign and seal.
  2. Edit the issue description: the panel shows what changed since the seal.
  3. Another approver chooses Approve these changes and gives a reason.
  4. Jira administrator: add the Require Valid LedgerSeal validator to the release transition of the workflow. Without it, LedgerSeal reports changes but does not block.

LedgerSeal guide

Get it on Atlassian Marketplace

DefinitionGuard (minutes, plus the gate)

  1. Open an issue and add the Definition of Done panel from the issue's app button. A built-in checklist for the issue type is already there.
  2. Tick items, add evidence where an item asks for it, or waive an item with a reason.
  3. Jira administrator: add DefinitionGuard DoD Enforcement to every transition into a Done status, then publish the workflow.
  4. Project administrator: open Project settings, DefinitionGuard and check that every completion transition is gated.

DefinitionGuard guide

FourRealities (about 10 minutes)

  1. Open Four Realities in the project's navigation. The first open builds the project's view; after that it is refreshed each day.
  2. Link each issue to its decision record: a Confluence page on your site, or a decision issue.
  3. Connect GitHub, Bitbucket or GitLab to Jira if you have not, so the Code check sees pull requests.
  4. Read the issue's four checks. The Process check looks for a Definition of Done record and the Audit check for an approval seal; on a site without DefinitionGuard and LedgerSeal, those two show Not used on this site and are not scored.
