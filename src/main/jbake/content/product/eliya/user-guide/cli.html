User guide

The asymm CLI

A small, focused command-line tool installed alongside Eliya at /usr/bin/asymm. The unified entry point for Asymm Systems products — Eliya today, Dial and Forensics in future phases.

Design philosophy

  1. Multi-product, not Eliya-specific. The pattern asymm <product> <command> scales as Asymm Systems ships additional products (Eliya, Dial, Forensics). The CLI is the unified entry point.
  2. Wrap real functionality, never simulate it. Every command in the CLI wraps a genuinely useful operation. No placeholder commands that print "Coming Soon."
  3. Phase-aligned scope. The Phase 1 CLI ships only commands that work today. Phase 2 and Phase 3 commands are documented as roadmap, not stubbed in Phase 1 builds.

Phase 1 commands (current)

Each command wraps an existing operation — no new engineering primitives required.

Command Purpose
asymm Top-level help with installed Asymm products
asymm version CLI version + installed Asymm products
asymm eliya Eliya subcommand help
asymm eliya version Eliya JDK version, build info, vendor strings
asymm eliya info Diagnostic environment info — JAVA_HOME, ELIYA_DIAGNOSTIC_PATH, ELIYA_SERVICE_NAME / ELIYA_REPLICA_NAME resolution with the three-level path layout, container detection, GC selection, JFR status
asymm eliya verify Verify Eliya installation integrity against published checksums
asymm eliya doctor Configuration sanity check — diagnostic paths writable, log directories exist, JFR can write to expected paths
asymm eliya versions List Eliya versions with LTS status, upstream base, support windows
asymm eliya versions --lts Filter to LTS-only versions
asymm eliya schedule Show Eliya release schedule with quarterly CPU targets
asymm eliya schedule --upcoming Show only upcoming (not yet shipped) releases
asymm eliya schedule --full Show full schedule — shipped + upcoming

Phase 2 roadmap (planned)

Documented as roadmap for Phase 2 (post-seed). Wrappers around the bundled tools (Eclipse MAT, async-profiler) and JFR conveniences.

Command Wraps Purpose
asymm eliya profile <pid> JFR or async-profiler (auto-selected) CPU profiling with sensible defaults
asymm eliya profile --hw-counters <pid> async-profiler Hardware performance counter analysis
asymm eliya profile --wall <pid> async-profiler Wall-clock thread profiling
asymm eliya profile --ttsp <pid> async-profiler Time-to-safepoint sampling
asymm eliya profile --alloc <pid> JFR Memory allocation profiling
asymm eliya analyze-heap <hprof> Eclipse MAT headless Leak Suspects HTML report
asymm eliya analyze-heap --duplicates <hprof> Eclipse MAT headless Duplicate object analysis
asymm eliya analyze-heap --histogram <hprof> Eclipse MAT headless Class histogram with retained size
asymm eliya analyze-heap --oql 'SELECT...' <hprof> Eclipse MAT headless Custom OQL query
asymm eliya jfr start <pid> jcmd <pid> JFR.start Start ad-hoc JFR recording
asymm eliya jfr dump <pid> jcmd <pid> JFR.dump Dump current JFR recording
asymm eliya jfr stop <pid> jcmd <pid> JFR.stop Stop JFR recording
asymm eliya jfr scrub <recording> JFR file rewriter Sanitise JFR recording for sharing

Optional tool installers. Phase 2 bundles Eclipse MAT (headless) and async-profiler by default. Engineers wanting the full Eclipse MAT GUI (for interactive heap analysis on workstations), JITWatch (for JIT compilation visualisation), or JOL (for object layout inspection) can install these on-demand rather than carrying them in the default Eliya distribution. Keeping the default install lean preserves image size and attack surface; opt-in installers keep the option open.

Command Installs Use case
asymm eliya install-mat-gui Eclipse MAT (full GUI build, large) Interactive heap analysis on engineer workstations
asymm eliya install-jitwatch JITWatch JIT compilation visualisation
asymm eliya install-jol Java Object Layout Object layout inspection

Platform note. The asymm CLI ships at /usr/bin/asymm (symlinked from ${JAVA_HOME}/bin/asymm) on Linux. Phase 2 macOS support uses /usr/local/bin/asymm. Phase 3 Windows support uses %PROGRAMFILES%\Asymm\eliya\bin\asymm.exe. All platforms share the same command structure documented above.

Phase 3 roadmap (Asymm Forensics)

Documented as roadmap for Phase 3 (post-Series-A). Invoke the Asymm Forensics product for cross-correlation diagnostic analysis.

Command Purpose
asymm forensics analyze <bundle> Cross-artifact correlation analysis
asymm forensics ingest --jfr <recording> Add JFR recording to analysis
asymm forensics ingest --heap <hprof> Add heap dump to analysis
asymm forensics ingest --threads <jstack> Add thread dump to analysis
asymm forensics ingest --gc-log <path> Add GC log to analysis
asymm forensics ingest --crash <hs_err> Add crash log to analysis
asymm forensics report Generate cross-correlation report
asymm forensics report --compliance pci-dss PCI DSS-aligned audit report
asymm forensics report --compliance hipaa HIPAA Technical Safeguards report
asymm forensics report --compliance sox SOX IT general controls report

The compliance report variants ship aligned with Eliya's Phase 4 profile namespace as those profiles ship. PCI DSS, HIPAA, and SOX are the initial three (highest demand based on early Phase 4 waitlist signals); FedRAMP, GDPR, ISO 27001, SOC 2, and combined-profile reports (Healthcare-Payment, Financial-SaaS, Federal-Defense, etc.) follow as customer demand justifies. See flag architecture for the Phase 4 profile namespace.

Versioning and compatibility

The asymm CLI follows independent SemVer:

  • asymm 1.x supports Eliya 25.0.x (Phase 1)
  • asymm 1.1+ supports Phase 2 diagnostic subcommands
  • asymm 2.x will accompany Asymm Forensics general availability
  • Backward-compatible commands within major versions; breaking changes require a major version bump

CLI version is decoupled from Eliya version. A user with Eliya 25.0.5 might have asymm 1.3 if Phase 2 tooling has matured.

Release cadence. The asymm CLI releases alongside Eliya CPUs by default (quarterly), with patch versions (1.0.x → 1.0.y) for CLI-specific bug fixes between Eliya CPUs as needed. The CLI is small enough that breaking changes are rare; the SemVer commitment is conservative.
